### Triage outcome — 2026-08-15

The owner chose to keep the release independent of its launch mechanism.
RoonScape remains one foreground command: it does not daemonize, restart
itself, know about `startx`, or require a particular service manager. The
Reference Deployment will have its guarded `startx` graphical session launch
that command. Deployment-specific recovery may restart the command after a
failure while respecting a successful intentional exit, but that policy and
its implementation remain with the unattended-deployment profile rather than
the RoonScape runtime or this ticket. Other owners remain free to launch or
supervise the same command differently.

Release tags use the exact form `v<package-version>`. Tag-triggered automation
must verify that the tag matches the package version before invoking the
repository packaging command and publishing a normal GitHub Release. A
mismatch fails before publication.

## Agent Brief

**Category:** enhancement

**Summary:** Publish version-matched Linux release artifacts and document a
supervisor-neutral owner, developer, and deployment lifecycle.

**Current behavior:** The repository has a reproducible packaging command that
builds and verifies a relocatable x86-64 Linux archive and SHA-256 checksum.
There is no tag-triggered publication workflow or published release contract.
Owner documentation still leads through the old source-oriented configuration
flow, while the product and unattended-deployment requirements still describe
independent bridge and renderer supervision that conflicts with the
launcher-managed runtime session.

**Desired behavior:** A version tag matching the package version publishes the
existing package command's archive and checksum as a normal GitHub Release.
Documentation gives release owners one coherent path from download through
updates, gives source developers the production-equivalent npm workflows while
retaining focused workflows, and consistently treats `roonscape` as a
foreground command independent of how a RoonScape Host launches it. The
Reference Deployment records guarded `startx` as its launch mechanism, while
the unattended-deployment effort retains ownership of its profile, recovery
policy, privileged host changes, and compatible-host acceptance.

**Key interfaces:**

- The repository packaging command remains the sole implementation of release
  staging, archive construction, and checksum generation; automation invokes
  it rather than reproducing those steps.
- A tag named `v<package-version>` is the publication contract. Automation
  rejects a tag that does not exactly match the package version before it
  publishes anything.
- The public `roonscape` command remains a foreground process with no built-in
  daemonization, restart loop, `startx` knowledge, or mandatory service
  manager.
- Release-owner documentation and source-developer documentation present
  separate entry paths without describing different runtime behavior.
- Product and unattended-deployment requirements use the launcher-managed
  bridge-and-renderer session and assign boot integration and recovery to the
  deployment profile.
