# 08 — Recover and expose diagnostics

**What to build:** Make the bridge and renderer tolerate ordinary failures and
start in either order without intervention. When troubleshooting is requested,
the owner can enable a compact diagnostics overlay; during normal listening,
the viewer sees no diagnostic UI.

**Blocked by:** 04 — Present live Now Playing and artwork; and 05 — Make
playback and progress truthful.

**Status:** done

- [x] Either process can start first or restart independently, and the renderer
      reconnects indefinitely without terminating its own session.
- [x] Every renderer connection receives the latest complete snapshot
      immediately; disconnected periods never leave stale Now Playing content
      presented as current.
- [x] Message size, frame count, and pending output are bounded; a stalled
      renderer can be disconnected instead of causing event-history growth.
- [x] Artwork and transition cleanup remain bounded across disconnects,
      reconnects, and rapid presentation changes.
- [x] An overlay enabled through RoonScape Host configuration reports memory,
      frame timing, artwork dimensions, connection state, and state revision and is
      disabled by default.
- [x] An IPC smoke check restarts each process once and confirms reconnection,
      current-state replay, and truthful availability.
- [x] Automated checks cover malformed or oversized frames, stalled clients,
      process order, and reconnect behavior without asserting private helpers.

### Agent Brief

**Category:** enhancement

**Summary:** Make both processes independently recoverable and expose optional
local diagnostics.

**Current behavior:** Fixture mode opens a bounded local socket and sends the
current snapshot to one renderer connection, but the renderer exits when its
counterpart is absent and neither process reconnects. No diagnostics overlay or
stalled-client handling exists.

**Desired behavior:** Either process can start or restart first. The renderer
reconnects indefinitely, disconnected periods never preserve stale Now Playing,
and an owner can opt into a compact diagnostics overlay without affecting the
normal viewer-facing display.

**Key interfaces:**

- IPC transports only the latest complete bounded snapshot and disconnects a
  stalled consumer rather than accumulating history.
- Renderer connection state drives truthful unavailable content and retry
  behavior.
- Host configuration enables an overlay for memory, frame timing, artwork
  dimensions, connection state, and revision; it remains disabled by default.

**Acceptance criteria:**

- [x] Both processes tolerate either startup order and ordinary independent
      restarts without terminating the other's session.
- [x] Every renderer connection receives current state immediately and no
      disconnected interval shows stale Now Playing as current.
- [x] Message, frame, pending output, artwork, and transition state remain
      bounded under malformed, oversized, stalled, and rapid-change cases.
- [x] The optional overlay reports the required diagnostics and is absent by
      default.
- [x] Automated tests and a local IPC smoke check cover process order,
      reconnects, restarts, framing failures, and stalled clients.

**Out of scope:**

- Service installation, graphical-session supervision, and host boot setup.
- A network diagnostics endpoint or permanent viewer-facing diagnostics.
