# 03 — Select and follow the Display Output

**What to build:** Give the owner a one-time RoonScape Host workflow for
discovering and saving one physical Display Output, then continuously resolve
the Display Zone that contains it. The viewer follows that physical output
through ordinary Roon grouping changes and never switches to whichever
unrelated zone becomes active.

**Blocked by:** 02 — Explain Roon connection availability.

**Status:** ready-for-agent

- [x] A practical RoonScape Host workflow lists discoverable outputs and saves
      one Display Output without requiring an onscreen or network settings
      interface.
- [x] Display Configuration is stored separately from Roon authorization state
      and can be changed without changing Roon playback.
- [x] Initial zone state, grouping, ungrouping, and zone renaming all resolve
      the configured Display Output to its current Display Zone.
- [x] Removal or invalid configuration produces output unavailable and clears
      stale Now Playing content rather than selecting a fallback output.
- [x] The viewer presents the Display Zone name under the label **Zone** and
      never exposes the internal Display Output identity.
- [x] Source-event tests cover full zone state, grouping, ungrouping, renaming,
      removal, and unrelated active-zone changes.

### Agent Brief

**Category:** enhancement

**Summary:** Select one physical Display Output and follow its containing
Display Zone through Roon grouping changes.

**Current behavior:** Availability can be represented by the shared contract,
but RoonScape has no Display Configuration or deterministic way to choose the
playback context it should present.

**Desired behavior:** An owner can discover and save one Display Output from
the RoonScape Host. Every relevant Roon update resolves that output to its
current Display Zone without following unrelated activity or silently choosing
a fallback.

**Key interfaces:**

- Display Configuration stores the selected Display Output independently from
  Roon authorization state.
- The host workflow lists discoverable outputs and saves the selection without
  an onscreen or network settings interface.
- Zone-state handling resolves full updates and grouping deltas into a complete
  snapshot containing only the viewer-facing Display Zone name.

**Acceptance criteria:**

- [x] A practical host command discovers outputs and saves one Display Output.
- [x] Grouping, ungrouping, renaming, and initial state resolve its current
      Display Zone consistently.
- [x] Removal or invalid configuration produces output unavailable and clears
      stale Now Playing instead of selecting another output.
- [x] The screen labels the Display Zone as **Zone** and never exposes Display
      Output identity.
- [x] Source-event tests cover the resolution cases and unrelated active-zone
      changes.

**Out of scope:**

- Automatic active-zone selection, fallback outputs, or multi-zone display.
- A settings screen, network configuration service, or Roon Control.
